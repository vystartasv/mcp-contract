Offline contract checks / mcp-contract

Know your MCP contract before an agent does.

A dependency-free local CLI for checking MCP-like tool manifests and JSON-RPC fixture transcripts before a connection exists.

The useful boundary

A small checker for the risky edges.

The wedge is deliberately narrow: validate the contract around tools, transcripts, and reviewable changes while everything is still a file.

01 / manifests

Check the tool list.

Validate names, descriptions, bounded input schemas, required fields, duplicates, and unknown fields.

02 / transcripts

Match the conversation.

Check JSON-RPC 2.0 tools/list request and response IDs, result shape, errors, and ordering.

03 / review

Make change visible.

Diff tool names and definitions deterministically, or emit an escaped HTML report for a bounded failure review.

How it works

Static inputs. Stable answers.

Build

Compile the standalone Bun binary from the checked-in source.

Load

Read one manifest or JSONL transcript within the documented bounds.

Validate

Apply the focused contract and collect stable diagnostics.

Compare

Diff sorted tool changes without semantic schema equivalence.

Review

Use exit codes, text diagnostics, or escaped report HTML.

Explicit boundaries

Useful because it stops here.

Included

Offline manifest checks, transcript correlation, deterministic diffs, bounded diagnostics, and HTML-escaped reports.

Not included

No MCP server, transport, network request, URL following, tool execution, agent framework, telemetry, or generic JSON Schema implementation.

Contract limits: input is capped at 1 MiB; events at 256 KiB; tools at 1,000; schema depth at 12; diagnostics at 100. Notifications, batch JSON-RPC, $ref, combinators, pagination, and vendor extensions are dropped deliberately.

Quickstart

Check a fixture in one shell.

Requires Bun 1.3+. The CLI uses no API key and sends no requests.

git clone https://github.com/vystartasv/mcp-contract.git
cd mcp-contract
bun install --frozen-lockfile
bun run build
./dist/mcp-contract check fixtures/valid-manifest.json

Verification / local evidence

  • Valid and invalid manifest branches.

  • Success is exit code 0; contract invalid is 2.
